# Native application validation — 11 November 2026

This report records development evidence for Cloud Job Orchestrator 1.1.0. It does not claim a public
release, installation, signing or exact-main hosted acceptance before those separate gates run.
Earlier illustrated Office guides retain their explicitly recorded historical source baseline.

## Application evidence

The complete `pilot-007` Windows ZIP was safely relocated and its actual Electron/Rust/PostgreSQL
application launched twice using a new marked synthetic profile and a system-only executable PATH.
Both visible native windows completed normal exit 0. No normal application profile or Docker was
opened. The candidate honestly records dirty development source at baseline
`66953562e528dd2e88397029a5092a57ac9bcda6`; clean post-commit/main packaging is a separate gate.

The real controls prepared and edited workflow data, previewed dependency waves and explicitly
submitted it. Original PostgreSQL workers produced the independently authored `RELEASE READY` and
SHA-256(`abc`) outputs. Import, cancellation, malformed/duplicate JSON refusal and new-file-only
captured result export were exercised. An attempted overwrite preserved the previous exact bytes.
The Unicode expansion case genuinely exceeded the original worker output bound, entered dead-letter
state and left its dependent blocked. No artificial success or substituted in-memory backend was used.

A leased delayed job was active when Quit was requested. The actual OS window displayed its finishing
state while the owner remained alive. Normal service completion stopped the owned PostgreSQL cluster;
the parent required exit 0 and absence of its owner PID file. Restart retained exact earlier results,
completed in-flight work and a genuinely unclaimed ready dependent. This is event/state evidence, not
a universal shutdown-time bound or a guarantee about abrupt OS termination.

Both launches used an explicit inert proxy override. The native browser resolved the owned origin to
DIRECT, its proxy received zero requests and the private RPC has a separate direct-only HTTP agent.
Normal browser activity made zero outside-origin requests. This is scoped application proof, not an
OS-wide network capture or proof about unrelated installed software.

## Genuine issues found and corrected

PostgreSQL truncates `cluster_name` at its documented name bound. The first owned native probe
authenticated successfully but its strict name check failed while version and canonical directory
matched. The derived cluster name now fits that bound and the strict identity checks remain.
The failed cluster shut down normally and its synthetic profile/log were preserved.

The published crate layout includes license directories; the packager now retains bounded actual
license files from the Windows normal-dependency graph, the Rust standard-library copyright notice,
PostgreSQL terms and separate Microsoft runtime terms. Nothing is replaced with a generic invented
license. Official provider bytes and Microsoft Authenticode/company identity are verified before use.

One UI probe incorrectly checked the HTML document title for a native OS-window close message.
The oracle now reads the actual BrowserWindow title. The original failed test is preserved rather
than counted as a pass. A complete ZIP initially refused a vendor file's pre-1980 timestamp; standard
ZIP timestamp clamping now handles that metadata without changing payload bytes, with a real regression.

Source snapshots now use Git's tracked/nonignored authored inventory rather than scanning ignored
developer configuration. The normal app explicitly avoids inherited proxy settings for its browser
and private API. No source-private credential, system service, global toolchain or Docker repair was added.

## Limits and next acceptance

Windows x64 portable and unsigned only; no MSI, macOS/mobile native package, signing, notarization,
clean-machine or OS-shell install claim is made. Data is owner-local plaintext, not a multi-user
authorization service. Existing namespace/alias checks are static admission and do not protect
against a malicious concurrent writer using the same OS account. Open only owned/trusted PostgreSQL
profiles. Closed-tree limits are not continuous storage quotas. Newest-event windows omit older
history; results and explanatory inspections are separate captures. Checksums are not signatures.

Exact PR/main source checks, actual processed CodeQL (preserving original Rust/JavaScript identities
and adding Python), real PostgreSQL integration and complete clean-source native acceptance must
pass before maintainer-reviewed release and installation. Full package uploads are disabled for ordinary
push/PR runs; only bounded proof/screenshots are retained for one day. A trusted-main manual opt-in is
required to retain a complete unsigned package.

Primary references are linked in the [native guide](../native-application.md).

## First hosted acceptance corrections

The first native CI run reached the real dashboard but the completion oracle read the jobs table
immediately after clicking Refresh. The application intentionally clears stale rows before its
asynchronous response completes; repeatedly clearing and reading that transient view timed out on
the hosted runner. The oracle now requires Refresh to become enabled before interpreting the new
captured rows, keeping the same15-second worker observation deadline. A held-response browser
regression verifies both the empty/disabled intermediate state and the completed rendered state.
This was a consumer synchronization error, not evidence of a failed PostgreSQL worker. A second
hosted run passed that initial workflow and exposed the same immediate-read mistake in the Unicode
dead-letter observation. Both now use one completion-aware refresh helper, and the initial workflow
requires both independent expected worker outputs in the completed capture before advancing.

Actual CodeQL also identified three check-then-open locations. Native file reads now open first,
bind the named path to that same regular, single-link descriptor, and consume bounded bytes only
from that descriptor. The source/runtime fingerprint builder reuses this reader instead of reopening
paths after checking them. A real replacement-after-open fixture must fail while preserving both
the old file and its replacement. No query or finding is suppressed; fresh processed scans remain
required before acceptance.
